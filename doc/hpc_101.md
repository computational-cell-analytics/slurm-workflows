# HPC 101

## Working on the cluster
A great overview about the work on the cluster is the [GWDG HPC Documentation](https://docs.hpc.gwdg.de/index.html) provided by the GWDG.
It's a great place to look for answers if you have questions going beyond the initial steps provided here.

## Navigating the bash terminal
If you are not familiar with the interface you see, a bash terminal, I can suggest further reading [here](https://cs.lmu.edu/~ray/notes/bash/).
Some of the most basic commands:
```bash
# list files/directories
ls
# change directories
cd target_directory_name
# go back a single directory
cd ..
# go to your home directory
cd ~
# go to the previous directory you were in
cd -
# show path of the current directory
pwd
# exit the connection to the cluster
exit
# copy a file
cp existing_file copied_file
# rename a file
mv old_file_name new_file_name
# remove a file (take care, the removed file(s) can NOT be recovered)
rm file
```

## Quota

Each project possesses a specific limit of storage space and inodes. The documentation can be found in the [GWDG Docs](https://docs.hpc.gwdg.de/how_to_use/storage_systems/quota/index.html).
The usage can be checked on the cluster using:
```bash
# check usage of user and project
show-usage
```

## Use screens

Screens are a way to run processes without requiring an active connection to the cluster. They are also great to have multiple processes at the same time.
Create and manage screens using `tmux`, e.g.
```bash
# create a screen
tmux new -s 0
# resume a screen
tmux a -t 0
```
If you are in a screen you can access functionalities by pressing `Ctrl`+`b` and an additional key, which is pressed afterwards:
* Detach from a screen: `Ctrl+b`--> `d`
* Overview over active windows: `Ctrl+b`--> `w`
* Enable viewing mode: `Ctrl+b`--> `[` (exited using `Ctrl`+`c`)

Exit a screen using `exit`.
Generally, most processes which go beyond simple actions (e.g. copying or deleting small amounts of data) like scripts for neural network application should be performed using [slurm jobs](https://docs.hpc.gwdg.de/how_to_use/slurm/index.html).
Slurm jobs are used for transforming data to MoBIE format, copying data to the S3 cluster, applying neural networks for segmentation and detection.

## File premissions
On the cluster, multiple users work on the same project. The files and directories have different permissions, depending on who created them. See the [documentation](https://docs.hpc.gwdg.de/how_to_use/data_sharing/managing_permissions/index.html).
If you want to share data with other members of the project, they have to be owned by the project group. The owner is called `HPC_<group_name>`, e.g. for the HPC project `nhr_ni_test_28507` this would be `HPC_nhr_ni_test_28507`.
To recursively change the permissions of the current working directory, use
```bash
chgrp -Rh HPC_<group_name> .
# e.g. chgrp -Rh HPC_nhr_ni_test_28507 .
```

## Advanced scripts/functions

**List files in current directory that match a pattern**
```bash
find . -maxdepth 1 -name "pattern*with*wildcards" -print
```

**Rename multiple files in the current directory**
Example ([Source](https://stackoverflow.com/questions/6840332/rename-multiple-files-by-replacing-a-particular-pattern-in-the-filenames-using-a)):

Folder which contains the files `IMG_01.jpg`, `IMG_02.jpg`, `OLD_IMG_03.jpg`
```bash
for f in *.jpg; do mv "$f" "$(echo "$f" | sed s/IMG/VACATION/)"; done
```
now contains `VACATION_01.jpg`, `VACATION_02.jpg`, `OLD_VACATION_03.jpg`.

**Check disk usage of storage space or inodes of directories matching pattern**
```bash
du -d1 -B1 <patttern> | awk '$1 >= <size in bytes>' | numfmt --to=iec
# e.g list all directories larger than 50 GB, which match the cochleae format, e.g. M_AMD_000117_L
du -d1 -B1 *_*_*_* | awk '$1 >= 50*1024^3' | numfmt --to=iec
# do something similar for inodes: directories with more than 10k inodes
du --inodes -d1 *_*_*_* | awk '$1 >= 10*1024' | numfmt --to=iec
```

**Check job submissions**
```bash
squeue --me
```
Show a longer job name:
```bash
squeue --me -o "%.18i %.9P %.25j %.8u %.2t %.10M %.6D %R"
```

### Working with your `.bashrc`

**Creating aliases**

Alias functions can be used to create custom commands. They are defined in `~/.bash_aliases` and are updated when you start a new bash terminal or you source them using `source ~/.bash_aliases`.
To automatically source the alias functions, add the following code lines to your `.bashrc`:
```bash
# Alias definitions.
# You may want to put all your additions into a separate file like
# ~/.bash_aliases, instead of adding them here directly.
# See /usr/share/doc/bash-doc/examples in the bash-doc package.

if [ -f ~/.bash_aliases ]; then
    . ~/.bash_aliases
fi
```
Some example to put in `.bash_aliases`:
```bash
# edit the ownership of files/directories in the current directory to set them to the access rights of the whole group
alias editgroup='chgrp -Rh HPC_nhr_ni_test_28507 .'
# edit the access rights
alias editrights='chmod -R g+rwX .'
# fix certain project folders to navigate quickly
export COCHLEA_DIR='/path/to/cochlea-lightsheet'
export MOBIE_DIR="$COCHLEA_DIR/mobie_project"
```
When `.bash_aliases` has been sourced, the access rights of the current directory can be changed using
```bash
editrights
```
which is then equivalent to writing:
```bash
chmod -R g+rwX .
```
